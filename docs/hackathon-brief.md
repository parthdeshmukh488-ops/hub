## The challenge

- Find a real problem and explain who you're solving it for.
- Build a working prototype that uses at least one Solana feature (payments, Solana Pay,
  privacy, tokenization, stablecoins, digital ownership, or an existing Solana app).
- Make the product easy for its intended users to understand and use.
- Explain what makes the idea useful and how you would reach your first users.
- "Start small: one useful feature that works is enough for a first prototype."

## Judging criteria

1. **Useful idea**: does it solve a clear problem?
2. **Working prototype**: can you demonstrate the core idea?
3. **Clear role for Solana**: does using Solana help the product?
4. **Potential to grow**: who would use it, and why?

## How we picked the idea

Used on 2026-09-29 to compare the ideas in the idea book (see the transcript). Each candidate was scored 1–5 on:

| Criterion | Question |
| --- | --- |
| Problem | Is there a specific person with a specific pain, and is today's workaround bad? |
| Why Solana | Would the product break or get much worse without Solana? |
| Buildable | Can the core flow run end to end on devnet by Oct 3? |
| Demo | Can a judge see it work in about 60 seconds? |
| First users | Is there a named, reachable first group (ideally at WHU or in Germany)? |
| Legs | Would we keep building it for Colosseum? |

**Why Solana** and **Buildable** were knockouts: a score of 2 or less dropped the idea.
