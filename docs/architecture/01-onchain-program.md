# Leash program specification

> **Status:** v1 draft, normative. This is the primary contract of the system. The SDK (WS2), indexer (WS4), web app (WS6) and x402 layer (WS3) are written against this document before the program exists. WS1 implements exactly this. Any deviation needs an ADR and a version bump ([04-conventions.md](04-conventions.md#6-changing-a-contract)).

## 1. Principles

1. **Fail closed.** `pay` either moves exactly the requested amount to an allowed payee, or fails and moves nothing. It never "succeeds" without paying.
2. **The allowance is the ceiling.** Leash never holds funds and never duplicates the budget. The per-period or total budget lives in the Subscriptions delegation (invariant I1). Leash adds the rules the allowance cannot express.
3. **Deterministic evaluation.** Payment evaluation is a pure function of the accounts, the arguments and the clock. The TypeScript evaluator in the SDK must reproduce it exactly; shared test vectors prove it ([§11](#11-testing-requirements)).
4. **Everything observable.** Every state change emits an event through Anchor `emit_cpi!` (self-CPI, so events survive log truncation).
5. **Least authority.** The agent key can only act on its own Agent account; the guardian can only stop things; the facilitator never appears in instruction accounts.

## 4. Accounts

All accounts start with the Anchor 8-byte discriminator, then `version: u8` and `bump: u8`. Integer fields are little-endian; timestamps are Unix seconds (`i64`); amounts are token base units (`u64`). Each account ends with a zeroed `reserved` array so later versions can append fields without reallocating.

## 5. Enums

Stored as `u8`. The numeric values are part of the contract and never change; new variants are appended. Borsh stores an enum as its variant index, so the variants are declared (and listed in the IDL) in value order. `DenialReason` is the one enum whose codes start at 1: code *n* is stored as *n − 1*. Decoders read the variant name through the IDL ([ADR](../adr/20260930-ws1-program-interface.md)).

| Enum | Values |
| --- | --- |
| `AgentStatus` | `Active = 0`, `Frozen = 1` |
| `FreezeReason` | `None = 0`, `Owner = 1`, `Guardian = 2`, `Tripwire = 3` |
| `PayeeMode` | `AllowListOnly = 0`, `AnyPayee = 1` |
| `RequestStatus` | `Pending = 0`, `Approved = 1` |
| `DelegationKind` | `Fixed = 2`, `Recurring = 3` (same numbers as the Subscriptions account discriminators) |

### `DenialReason`

| Code | Name | Strike? | Meaning |
| --- | --- | --- | --- |
| 1 | `PrincipalFrozen` | no | The owner's global switch is off |
| 2 | `AgentFrozen` | no | This agent is frozen |
| 3 | `AgentExpired` | no | `now >= policy.valid_until` |
| 4 | `PayeeNotAllowed` | **yes** | Destination owner is not on the allowlist |
| 5 | `ExceedsPaymentLimit` | **yes** | Above `max_per_payment`, and approvals cannot cover it |
| 6 | `ApprovalRequired` | no | Above `max_per_payment` but within `max_per_request`: use `request_payment` |
| 7 | `ExceedsPayeePaymentLimit` | **yes** | Above the payee's `max_per_payment` |
| 8 | `ExceedsPayeePeriodLimit` | no | The payee's period budget is used up |
| 9 | `VelocityExceeded` | no | Too many payments in the current window |
| 10 | `AllowanceExpired` | no | The Subscriptions delegation expired |
| 11 | `AllowanceExceeded` | no | Not enough allowance left in this period (or in total) |
| 12 | `InsufficientFunds` | no | The owner's token account holds less than the amount |

Strikes are reserved for reasons that signal manipulation or a bug: trying to pay someone off the list, or trying to pay far more than allowed. Running out of budget or hitting the rate limit is normal and never trips the wire.

## 6. Instructions

Common accounts used by every instruction that emits events (Anchor `#[event_cpi]`): `event_authority`, `program`. They are omitted from the tables below.

### 6.1 Owner and guardian instructions

| Instruction | Signer | Accounts (besides signer) | Args | Effect | Event |
| --- | --- | --- | --- | --- | --- |
| `initialize_principal` | owner (payer) | `principal` (init), `system_program` | `guardian: Option<Pubkey>` | Create principal | `PrincipalInitialized` |
| `set_guardian` | owner | `principal` (mut) | `guardian: Option<Pubkey>` | Set or clear the guardian | `GuardianChanged` |
| `freeze_principal` | owner **or** guardian | `principal` (mut) | – | `frozen = true` (idempotent; emits only on change) | `PrincipalFrozen` |
| `unfreeze_principal` | owner | `principal` (mut) | – | `frozen = false` (idempotent) | `PrincipalUnfrozen` |
| `create_agent` | owner (payer) | `principal` (mut), `agent` (init), `mint` | `agent_key: Pubkey, label: [u8;32], policy: Policy` | Validate policy; `agent_key` must not be the owner; `agent_count += 1` | `AgentCreated` |
| `update_policy` | owner | `principal`, `agent` (mut) | `policy: Policy` | Validate and replace the policy (counters are kept) | `PolicyUpdated` |
| `freeze_agent` | owner **or** guardian | `principal`, `agent` (mut) | – | `status = Frozen`, `freeze_reason = Owner` or `Guardian` (idempotent) | `AgentFrozen` |
| `unfreeze_agent` | owner | `principal`, `agent` (mut) | – | `status = Active`, reason `None`, `strikes = 0`, `strike_window_start = 0` (idempotent) | `AgentUnfrozen` |
| `close_agent` | owner (rent receiver) | `principal` (mut), `agent` (mut, close) | – | Requires `payee_count == 0 && open_requests == 0` (else `AgentNotEmpty`); `agent_count -= 1` | `AgentClosed` |
| `add_payee` | owner (payer) | `principal`, `agent` (mut), `payee_entry` (init) | `payee: Pubkey, label: [u8;32], limits: PayeeLimits` | `payee` must not be the agent key or the Agent PDA (`InvalidPayee`); `payee_count += 1` | `PayeeAdded` |
| `update_payee` | owner | `principal`, `agent`, `payee_entry` (mut) | `label: [u8;32], limits: PayeeLimits` | Replace label and limits (period counters are kept) | `PayeeUpdated` |
| `remove_payee` | owner (rent receiver) | `principal`, `agent` (mut), `payee_entry` (mut, close) | – | `payee_count -= 1` | `PayeeRemoved` |
| `approve_request` | owner | `principal`, `agent`, `request` (mut) | – | Requires `Pending` and not expired; sets `Approved`, `approved_at` | `RequestApproved` |
| `reject_request` | owner **or** guardian | `principal`, `agent` (mut), `request` (mut, close), `rent_receiver` (mut, must equal `request.rent_payer`) | – | `open_requests -= 1` | `RequestRejected` |

`PayeeLimits = { max_per_payment: u64, period_limit: u64, period_secs: u32 }`; `period_secs` must be > 0 when `period_limit` > 0 (else `InvalidPolicy`).

Idempotent instructions change nothing and emit nothing when there is nothing to change. `freeze_agent` on a frozen agent keeps the first reason; `unfreeze_agent` on an active agent leaves its strikes alone.

Every owner instruction checks `principal.owner == signer` and `agent.principal == principal` (Anchor `has_one` plus seeds). Guardian checks: `principal.guardian != Pubkey::default() && signer == principal.guardian`, otherwise `Unauthorized`.

### 6.2 Agent instructions

#### `pay(args: PayArgs)`: the only path to the owner's funds

`PayArgs = { amount: u64, reference: [u8; 32], memo: [u8; 64] }`

| # | Account | Mut | Signer | Notes |
| --- | --- | --- | --- | --- |
| 1 | `agent_key` | | ✓ | Must equal `agent.agent_key`. **Not** the fee payer in x402 flows. |
| 2 | `principal` | | | |
| 3 | `agent` | ✓ | | Seeds checked |
| 4 | `payee_entry` | ✓ | | **Optional.** Required when `payee_mode == AllowListOnly` |
| 5 | `request` | ✓ | | **Optional.** An approved `PaymentRequest` to consume |
| 6 | `request_rent_receiver` | ✓ | | **Optional.** Required iff `request` is present; must equal `request.rent_payer` |
| 7 | `delegation` | ✓ | | Subscriptions Fixed or Recurring delegation with `delegator == owner`, `delegatee == agent PDA`, `mint == agent.mint`, else `DelegationMismatch` |
| 8 | `subscription_authority` | | | Subscriptions SA PDA `["SubscriptionAuthority", owner, mint]`: owned by Subscriptions and the one the delegation names, else `DelegationMismatch` |
| 9 | `source_token_account` | ✓ | | The owner's **associated** token account for `mint`, the only one the delegation debits, else `DelegationMismatch` |
| 10 | `destination_token_account` | ✓ | | `mint` must match (`MintMismatch`); its **owner** is the payee wallet; not the source and not owned by the agent key or the Agent PDA, else `InvalidDestination` |
| 11 | `mint` | | | Must equal `agent.mint` |
| 12 | `token_program` | | | SPL Token or Token-2022, matching the mint |
| 13 | `subscriptions_program` | | | Must equal the Subscriptions program ID |
| 14 | `subscriptions_event_authority` | | | Subscriptions PDA `["event_authority"]` |
| – | remaining accounts | | | Forwarded untouched to the Subscriptions CPI (Token-2022 transfer-hook accounts). Empty for USDC. |

Steps:

1. Validate accounts (errors, never denials): signer, seeds, mint, token program, delegation ownership and version, both token accounts' mint, the source and destination rules of the table above, and `request_rent_receiver` present exactly when `request` is (else `RequestMismatch`). A delegation that is not a version-1 Fixed or Recurring account of the exact v1 size is rejected with `UnsupportedDelegation`.
2. Run `evaluate` (§7). If it returns a denial, **fail** with the matching `Denied*` error. Nothing is written.
3. Update counters as defined in §7.2 (velocity window, payee period, payee and agent totals). If a request was consumed, decrement `open_requests` and close it (rent to `request_rent_receiver`; the program closes it right after step 4).
4. CPI into Subscriptions (§8) with the Agent PDA signing as delegatee.
5. Emit `PaymentExecuted`.

#### `report_denied_attempt(args: PayArgs)`: leaves an on-chain trace of a blocked attempt

Accounts: `agent_key` (signer), `principal`, `agent` (mut), `payee_entry` (optional), `delegation`, `source_token_account`, `destination_token_account`, `mint`. All read-only except `agent`. Payment requests are not accepted here.

1. Validate accounts as in `pay`.
2. Run `evaluate`. If it would **allow** the payment, fail with `AttemptWouldSucceed`. This instruction can never move money, and cannot be used to record fake strikes against a payment that is actually allowed.
3. `stats.denied_count += 1`.
4. If `reason.is_strike()` and `policy.tripwire_max_strikes > 0` and the agent is active: roll the strike window (§7.2), `strikes += 1` (saturating). If `strikes >= tripwire_max_strikes`: `status = Frozen`, `freeze_reason = Tripwire`, `frozen_at = now`.
5. Emit `PaymentDenied`, and `AgentFrozen { reason: Tripwire }` if the wire tripped.

The SDK calls this after a `pay` simulation fails with a denial ([ADR-0002](../adr/0002-strict-pay-and-reported-denials.md)). The agent key pays its fee.

#### `request_payment(args: RequestArgs)`

`RequestArgs = { payee: Pubkey, amount: u64, reference: [u8; 32], memo: [u8; 64] }`

Accounts: `agent_key` (signer), `rent_payer` (signer, mut; usually the agent key), `principal`, `agent` (mut), `payee_entry` (optional), `request` (init, seeds with `agent.stats.request_nonce`), `system_program`.

Checks, in order. Each failure is an error and the transaction reverts:

1. Principal and agent not frozen, agent not expired (`DeniedPrincipalFrozen`, `DeniedAgentFrozen`, `DeniedAgentExpired`).
2. `policy.max_per_request > 0`, else `ApprovalsDisabled`.
3. `amount > policy.max_per_payment`, else `ApprovalNotNeeded`.
4. `amount <= policy.max_per_request`, else `DeniedExceedsPaymentLimit`.
5. Allowlist, when `AllowListOnly`: `payee_entry` must exist for `payee`, else `DeniedPayeeNotAllowed`.
6. `open_requests < MAX_OPEN_REQUESTS`, else `TooManyOpenRequests`.

Effects: create the request (`Pending`, `expires_at = now + request_ttl_secs`), `request_nonce += 1`, `open_requests += 1`. Event: `PaymentRequested`.

## 7. Evaluation

### 7.1 Order (normative)

`evaluate(principal, agent, payee_entry?, request?, delegation, source, destination, amount, reference, now) -> Result<(), DenialReason>`. The first failing check wins. Let `P = destination.owner`.

```text
 0. amount == 0                                  → error InvalidAmount (not a denial)
 1. principal.frozen                             → PrincipalFrozen
 2. agent.status == Frozen                       → AgentFrozen
 3. valid_until != 0 && now >= valid_until       → AgentExpired
 4. allowlisted := payee_entry present
                   && payee_entry.agent == agent && payee_entry.payee == P
    payee_mode == AllowListOnly && !allowlisted  → PayeeNotAllowed
 5. if request present (approved-request path):
        request.agent == agent, status == Approved, now < expires_at,
        request.payee == P, request.amount == amount,
        request.reference == reference          → else error RequestMismatch / RequestNotApproved / RequestExpired
        skip checks 6–8
 6. amount > max_per_payment:
        max_per_request != 0 && amount <= max_per_request → ApprovalRequired
        otherwise                                          → ExceedsPaymentLimit
 7. allowlisted && entry.max_per_payment != 0
        && amount > entry.max_per_payment        → ExceedsPayeePaymentLimit
 8. allowlisted && entry.period_limit != 0
        && rolled(entry.spent_in_period) + amount > entry.period_limit
                                                 → ExceedsPayeePeriodLimit
 9. velocity_max_payments != 0
        && rolled(velocity_count) + 1 > velocity_max_payments → VelocityExceeded
10. allowance pre-check on the delegation (§7.3)  → AllowanceExpired / AllowanceExceeded
11. source.amount < amount                       → InsufficientFunds
    → Allowed
```

Approved requests skip only the instant and per-payee limits (steps 6–8). The owner explicitly approved that exact payment. Freeze, expiry, allowlist, rate limit and the allowance ceiling still apply.

### 7.2 Leash windows (velocity, payee period, strikes)

Fixed-length windows that restart at the first event after the previous window ended. They are not aligned to calendar time.

```text
rolled(start, secs, counter, now):
    if start == 0 or now >= start + secs:  return (now, 0)
    else:                                  return (start, counter)
```

On a successful `pay`:

- **Velocity**, only if `velocity_max_payments > 0`: `(start, count) = rolled(...)`, then `count += 1`.
- **Payee period**, only if the payee entry matches the destination and `period_limit > 0`: `(start, spent) = rolled(...)`, then `spent += amount`. This also applies to approved requests, whose limit *checks* were skipped: the money was still spent with that payee.
- **Payee totals** (`total_paid`, `payments_count`) for a matching entry, and **agent totals** (`payments_count`, `total_paid`, `last_payment_at`): always.

A limit that is switched off (a count or amount of 0) never updates its window, so its stored counters stay as they were. Strikes use the same `rolled` function with `tripwire_window_secs`, and only when `tripwire_max_strikes > 0`. The test vectors pin all of this ([ADR](../adr/20260929-ws0-disabled-limits-are-not-tracked.md)).

### 7.3 Allowance pre-check

Leash reads the Subscriptions delegation (layout frozen at v1, [§8.3](#83-subscriptions-account-layouts-read-only)) and mirrors Subscriptions' own validation, so an exhausted budget becomes a clean `AllowanceExceeded` denial instead of an opaque CPI failure:

Expiry is **inclusive**, as in Subscriptions' `is_expired`: a delegation is expired only when `expiry_ts != 0 && now > expiry_ts`, so a payment at exactly `expiry_ts` is still allowed ([ADR](../adr/20260929-ws0-allowance-expiry-is-inclusive.md)). Leash's own `valid_until` and request `expires_at` are exclusive (`now >= …` means expired).

- **Fixed:** expired → `AllowanceExpired`; `amount > amount_remaining` → `AllowanceExceeded`.
- **Recurring:** expired → `AllowanceExpired`; `now < current_period_start_ts` → `AllowanceExceeded`; otherwise apply exactly the period roll-forward of Subscriptions' `validate_recurring_transfer`, including its expiry clamp (which only matters when `now == expiry_ts`: no fresh period opens at the expiry boundary); then `pulled + amount > amount_per_period` → `AllowanceExceeded`.

The pre-check never writes to the delegation. The Subscriptions CPI remains the authority: if the two ever disagree, the CPI fails and the transaction reverts (fail closed).

## 8. CPI into Subscriptions

### 8.1 Instruction

| Delegation kind | Discriminator | Data (73 bytes) |
| --- | --- | --- |
| Fixed | `4` (`TransferFixed`) | `[4] ‖ amount: u64 LE ‖ delegator: [u8;32] ‖ mint: [u8;32]` |
| Recurring | `5` (`TransferRecurring`) | `[5] ‖ amount: u64 LE ‖ delegator: [u8;32] ‖ mint: [u8;32]` |

`delegator` is the owner. The kind is read from byte 0 of the delegation account (2 = Fixed, 3 = Recurring).

### 8.2 Accounts (order is fixed by Subscriptions)

| # | Account | Flags |
| --- | --- | --- |
| 0 | delegation | writable |
| 1 | subscription_authority | readonly |
| 2 | source_token_account (delegator ATA) | writable |
| 3 | destination_token_account (receiver ATA) | writable |
| 4 | mint | readonly |
| 5 | token_program | readonly |
| 6 | **Agent PDA** (delegatee) | **signer** (via `invoke_signed` with seeds `[b"agent", principal, agent_key, [bump]]`) |

| 9.. | remaining accounts | forwarded as received |

Subscriptions then CPIs `TransferChecked`, with its Subscription Authority PDA as the SPL delegate. Call depth: Leash → Subscriptions → Token (2), plus the event self-CPIs of both programs. This is within Solana's limit.

## 11. Testing requirements

WS1 is done when all of these pass in CI (LiteSVM, with the real Subscriptions `.so` loaded):

1. **Policy test vectors.** Every case in `packages/contracts/test-vectors/policy.json` produces the expected outcome. The same file drives the TypeScript evaluator tests in WS2 (parity).
2. **Invariant tests**, one per invariant ([03-security.md](03-security.md#3-invariant-tests)). In particular:
   - no instruction sequence by the agent key moves more than the delegation allows (I1);
   - a non-allowlisted payee never receives funds (I2);
   - after `freeze_*` every `pay` fails, and only the owner can unfreeze (I3);
   - N strike reports freeze the agent (I4);
   - `report_denied_attempt` on an allowed payment fails (it can never pay).
3. **x402 shape test.** A transaction `[SetComputeUnitLimit, SetComputeUnitPrice, pay, Memo]` whose fee payer is a third key that appears in no instruction succeeds. Its inner instructions contain exactly one `TransferChecked`.
4. **Compute budget.** `pay` with no request stays under 100k CU. Record the measured figures in `programs/leash/CU.md`.
5. **Account-substitution tests.** Every account slot is fed a wrong-but-plausible account (another agent's payee entry, another owner's delegation, a wrong mint, a wrong token program) and must fail.

## 12. Upgrade and versioning

- Devnet: the upgrade authority is the deployer key (kept out of git).
- Pitch statement for production: the upgrade authority moves to a timelocked multisig or is revoked, so "nobody can change the rules" is literally true.
- Account `version` fields and `reserved` bytes allow append-only evolution. Instruction and event changes follow the contract-change process ([04-conventions.md](04-conventions.md#6-changing-a-contract)).

## 13. Decisions WS1 took ([ADR](../adr/20260930-ws1-program-interface.md))

| Question | Decision |
| --- | --- |
| Can Anchor 1.x `close` constraints be applied to `Option<Account>` (the `request` in `pay`)? | `pay` closes a consumed request itself with Anchor's `AccountsClose::close`: lamports to `request_rent_receiver`, account assigned to the system program and shrunk to 0 bytes. Anchor's exit skips closed accounts. |
| Subscriptions program ID on devnet: canonical ID deployed? | The canonical ID stays until WS0's devnet check says otherwise. If it is missing, deploy the audited source at a new ID and select it with a cargo feature `devnet-subscriptions`. |
| One `Payee` per `(agent, payee)`, or also per-principal shared payees? | Per agent only (least privilege). Shared payees can be added later without breaking changes. |
